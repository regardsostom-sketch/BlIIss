# BLISS Academy (Next.js + Tailwind + TypeScript + Supabase)

Студент регистрируется, выбирает уровень (A1…C1) и занимается по своей программе:
**программа → темы → подтемы → 6 разделов** (грамматика, лексика, аудирование, чтение, письмо, говорение).
Программы, темы и подтемы редактирует преподаватель.

## Запуск
1. `npm i`; скопируйте `.env.example` в `.env.local` и вставьте URL и anon key проекта Supabase.
2. Supabase → SQL Editor: выполните `supabase/schema.sql` (на чистом проекте), по желанию `supabase/seed.sql` (пример программы A1).
3. Supabase → Authentication → URL Configuration: укажите адрес сайта (для писем подтверждения).
4. Зарегистрируйтесь на сайте, затем в SQL: `update profiles set role='admin' where id='<uuid>';`
   Преподавателям выдавайте `role='teacher'`.
5. `npm run dev`. Деплой: Vercel (GitHub Pages не запускает Next.js с сервером).

## Как это работает
- **Регистрация.** Студент выбирает уровень. Ему автоматически назначается опубликованная программа этого уровня.
  Если программы ещё нет, она назначится сама, когда преподаватель её опубликует. Ошиблись с уровнем: `Студенты` → выбрать другую программу.
- **Преподаватель** (`Программы`): создаёт программу, добавляет темы и подтемы, меняет порядок (↑↓), переименовывает и удаляет.
  В каждой подтеме заполняет 6 разделов обычными формами: строка «текст до пропуска, слово, текст после», таблица слов, вопросы с кружком у верного ответа.
  Ошибки (не вписано слово, не отмечен верный ответ, ссылка не https) показываются сразу, и раздел с ошибкой не сохранится, так что ничего не пропадает молча.
  Кнопка «Как увидит студент» показывает раздел до сохранения (ответы в предпросмотре не записываются), а «Копировать подтему» делает копию вместе с содержанием.
  Новая программа это черновик, пока её не опубликуют.
- **Автопроверка:** грамматика (пропуски), лексика (карточки), аудирование и чтение (вопросы с выбором ответа).
  **Проверяет преподаватель:** письмо (текст) и говорение (аудиозапись, хранится в Supabase Storage, бакет `speaking`), страница `Работы` (вкладки «На проверке» и «Проверенные»: решение можно изменить).
  Студент видит отзывы в кабинете (блок «Отзывы преподавателя») и историю своих работ внутри подтемы; письмо, возвращённое на доработку, подставляется в поле для исправления.
  Запись голоса: до 3 минут, работает в Chrome, Firefox и Safari (iPhone); можно переслушать и записать заново.
- **Кабинет студента:** прогресс по программе, темам и подтемам; кнопка «Продолжить» ведёт к следующей незавершённой подтеме.
  Письмо и говорение считаются так: на проверке 50%, принято 100%.

## Заметки
- Прогресс по автопроверяемым разделам хранит лучший результат студента. В процент подтемы входят только заполненные разделы: пока в разделе нет упражнений, вопросов или задания, он не учитывается и не мешает завершить подтему.
- Аудио в «Аудирование»: вставьте ссылку на файл, либо оставьте пустой, и текст озвучит браузер студента.
- **Язык интерфейса:** переключатель РУС / ҚАЗ в шапке (запоминается в cookie). Весь студенческий интерфейс переведён.
  Админская часть (конструктор, студенты, проверка работ) только на русском.
- **Казахский в содержании** вводит преподаватель, всё необязательно: название программы, темы и подтемы (второе поле «Қазақша»),
  объяснение грамматики, задания письма и говорения, третий столбец в словах (`hello | привет | сәлем`). Если казахского варианта нет, показывается русский.
- **Видео и аудио:** в разделах «Грамматика» и «Аудирование» преподаватель нажимает «Загрузить файл» (видео `.mp4/.webm/.ogg`, аудио `.mp3/.m4a/.wav/.ogg/.aac`)
  или вставляет ссылку YouTube, Vimeo, `https://…/файл.mp4`. Файлы хранятся в Supabase Storage (бакет `media`), ссылка подставляется сама. Работают только ссылки https.
  Лимит файла 50 МБ (лимит бесплатного тарифа Supabase; при платном тарифе поднимите его в Storage → Settings и в `schema.sql`). Для длинных видео удобнее YouTube.
  Бакет `media` публичный: любой, у кого есть длинная случайная ссылка, увидит файл. Не загружайте туда ничего конфиденциального.
  Заменённые и убранные файлы из хранилища сами не удаляются (Supabase → Storage → media).
- Если `schema.sql` уже был выполнен до этих обновлений, выполните `supabase/migrate_update.sql`.
- `.env.local` не должен попадать в репозиторий (он в `.gitignore`).

## Почта: подтверждение email и восстановление пароля
На сайте есть «Забыли пароль?» (`/forgot` → письмо → `/reset`), повторная отправка письма подтверждения на странице входа
и обработчик ссылок из писем `/auth/callback`. Все письма отправляет Supabase, поэтому **ему нужен рабочий SMTP-сервер**:
встроенная почта Supabase Cloud рассчитана на тесты и пропускает лишь несколько писем в час, группе студентов этого не хватит.

**1. Адреса сайта.** Укажите публичный адрес сайта (например `https://trainer.example.kz`):
- Supabase Cloud: Authentication → URL Configuration → Site URL; в Redirect URLs добавьте `https://trainer.example.kz/**`.
- Свой Supabase (docker): в `.env` задайте `SITE_URL=https://trainer.example.kz` и `ADDITIONAL_REDIRECT_URLS=https://trainer.example.kz/**`.
- Если сайт стоит за обратным прокси (Caddy, Nginx), задайте `NEXT_PUBLIC_SITE_URL` в `.env.local` самого сайта.

**2. Свой SMTP.**
- Supabase Cloud: Authentication → Emails → SMTP Settings.
- Свой Supabase (docker), в `.env`: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_ADMIN_EMAIL` (адрес отправителя), `SMTP_SENDER_NAME`, затем перезапустите сервисы.
- Данные для SMTP даёт почтовый сервис или хостинг-провайдер. В письмах будут email студентов: если важно, чтобы они не уходили за рубеж, выбирайте казахстанский SMTP.

**3. Можно ли отключить подтверждение email.** Да: Authentication → Providers → Email → выключить «Confirm email»
(в docker: `ENABLE_EMAIL_AUTOCONFIRM=true`). Тогда студент входит сразу после регистрации.
Минус: на сайт можно зарегистрироваться на чужой адрес. SMTP всё равно нужен: письма восстановления пароля идут через него.

**4. Если ссылка из письма открывается в другом браузере** (письмо на телефоне, регистрация на компьютере), обычная ссылка не сработает.
Чтобы это работало, в шаблонах писем (Authentication → Emails → Templates) замените ссылку на
`{{ .SiteURL }}/auth/callback?token_hash={{ .TokenHash }}&type=email` (подтверждение) и
`{{ .SiteURL }}/auth/callback?token_hash={{ .TokenHash }}&type=recovery&next=/reset` (восстановление пароля).

## Ошибки
- Если действие преподавателя не удалось (нет прав, нет связи, запись уже удалена), сверху страницы появляется красная плашка с понятным текстом,
  а преподаватель остаётся на той же странице.
- Если страница не смогла загрузиться, показывается экран «Что-то пошло не так» с кнопкой «Повторить»; если не работает сам сайт, показывается `global-error`. Есть и страница «не найдено».

## Прогресс студентов (для преподавателя)
- **Студенты** (`/admin/students`): поиск по имени, по 20 на странице. У каждого: общий процент по программе, дата последней активности,
  метка «N дн. без занятий» (от 7 дней), число работ на проверке, смена программы.
- **Страница студента** (`Подробнее →`): блок «Что обсудить на следующем занятии» (работы на доработке, разделы с лучшим результатом ниже 70%, ждущие проверки),
  таблица «тема → подтема → 6 разделов» с процентами и история письменных и устных работ с отзывами и аудио.
- Проценты считаются так же, как в кабинете студента, поэтому цифры совпадают. Всё это только чтение: новых таблиц и миграций не нужно.
- Ограничение: сайт хранит лучший процент по разделу, а не ответы на отдельные вопросы. Поэтому видно, **где** студент слаб, но не **какие именно** ошибки он делал.
  Чтобы показывать конкретные ошибки, нужно начать сохранять ответы (отдельная доработка).

## Автопроверка письма и говорения (необязательно)
Работы студентов по-прежнему принимает или возвращает преподаватель. Автопроверка только добавляет **подсказку**: студент видит её сразу после отправки,
преподаватель видит её на странице «Работы». Если сервис не настроен или не отвечает, ничего не ломается: работа просто уходит преподавателю.

**Что проверяется**
- **Говорение**: [ai-pronunciation-trainer](https://github.com/Thiagohgl/ai-pronunciation-trainer) (open source, свой Python-сервис). Студент читает вслух фразу, которую задал преподаватель,
  а программа распознаёт речь и показывает точность произношения в % и слова, которые стоит потренировать (зелёные и красные).
  Работает с английским (и немецким). **Свободную речь («расскажите о семье») он оценить не может**: нужна фраза для чтения.
  Преподаватель вводит её в конструкторе, раздел «Говорение», поле «Фраза для автопроверки произношения». Пусто = запись проверяет только преподаватель.
- **Письмо**: ai-pronunciation-trainer письмо не проверяет, для этого подключён [LanguageTool](https://languagetool.org) (open source): орфография, грамматика, пунктуация.
  Он не оценивает, выполнено ли задание и достаточен ли объём, это решает преподаватель.

**Настройка**
1. Supabase → SQL Editor: выполните `supabase/migrate_ai.sql` (на новом проекте это уже есть в `schema.sql`).
2. Ключ `service_role` (Project Settings → API) в `.env.local` как `SUPABASE_SERVICE_ROLE_KEY`. Он нужен серверу, чтобы записать результат автопроверки так, чтобы студент не мог его подделать. Никому не показывайте и не коммитьте.
3. **Сервис произношения** (отдельный сервер, на Vercel он не запустится: Python, PyTorch, ffmpeg):
   `git clone https://github.com/Thiagohgl/ai-pronunciation-trainer`, `pip install -r requirements.txt`, установить `ffmpeg`, `python webApp.py`: сервис слушает порт 3000.
   Первый запуск скачивает модели распознавания речи. Есть и доработанная версия с Docker (trincadev/ai-pronunciation-trainer), см. её README.
   Адрес сервиса запишите в `PRONUNCIATION_API_URL`. Сайт обращается к нему только с сервера, поэтому открывать его студентам не нужно: закройте порт от внешнего мира, если сайт и сервис на одной машине.
4. **LanguageTool**: оставьте `LANGUAGETOOL_URL` пустым, чтобы использовать публичный `api.languagetool.org` (есть лимиты запросов, **тексты студентов уходят на этот внешний сервер**),
   либо поднимите свой: `docker run -d -p 8010:8010 erikvl87/languagetool` и укажите `LANGUAGETOOL_URL=http://localhost:8010`.
5. Перезапустите сайт.

**Заметки**
- Результат сохраняется в `submissions.ai_score` и `submissions.ai_report`, студент видит его и в «Мои отправленные работы».
- Защита от перегрузки: не больше 10 автопроверок за 10 минут на одного студента.
- Для распознавания нужен процессор (CPU) с запасом памяти; на слабом сервере проверка одной записи может занимать десятки секунд (таймаут 90 секунд).
- Формат ответа сервиса произношения разбирается с запасом, но проверьте один раз на живом сервисе: запишите фразу и посмотрите, что показал блок «Автопроверка».
